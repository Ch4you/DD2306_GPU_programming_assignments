# DD2360 HW1, Group 67

The report used a GeForce RTX 5070 Ti Laptop GPU (compute capability 12.0),
CUDA 13.5, Nsight Compute 2026.4, and Nsight Systems 2026.5.2 on Windows.
Set the architecture to match your GPU. Run the Windows commands below in
PowerShell with the x64 Visual Studio developer environment and CUDA, CMake,
Ninja, and the two Nsight CLIs on PATH.

## Q1. Vector addition

```powershell
nvcc -O3 -arch=sm_120 -lineinfo vector_add.cu -o vector_add.exe
ncu --section Occupancy --section LaunchStats -c 1 -o vector_512 .\vector_add.exe 512 1
ncu --section Occupancy --section LaunchStats -c 1 -o vector_263149 .\vector_add.exe 263149 1

'N,H2D_ms,Kernel_ms,D2H_ms' | Set-Content vector_timings.csv
foreach ($n in 512,2048,8192,32768,65536,131072,263149,524288,1048576,2097152,4194304,8388608) {
    .\vector_add.exe $n 20 | Add-Content vector_timings.csv
    if ($LASTEXITCODE -ne 0) { throw "Vector add failed at N=$n" }
}
```

Check the program's PASS output and read Achieved Occupancy in the Occupancy
section of each `.ncu-rep`. Run Nsight Compute from an administrator shell if
it reports `ERR_NVGPUCTRPERM`. For the stacked chart, plot the three timing
columns in milliseconds against `N`. The CSV rows use one warm-up and 20
timed repetitions.

## Q2. Matrix multiplication

```powershell
nvcc -O3 -arch=sm_120 -lineinfo matrix_mul.cu -o matrix_mul.exe
ncu --section Occupancy --section LaunchStats -c 1 -o matrix_small .\matrix_mul.exe double 128 256 32 1
ncu --section Occupancy --section LaunchStats -c 1 -o matrix_large .\matrix_mul.exe double 1024 8191 8197 1

$cases = (128,256,32),(256,512,256),(512,1024,1024),(768,4096,4096),
         (1024,8191,8197),(1280,9216,9216),(1536,10240,10240)
'Precision,M,N,P,H2D_ms,Kernel_ms,D2H_ms' | Set-Content matrix_timings.csv
foreach ($dims in $cases) {
    foreach ($precision in 'double','float') {
        .\matrix_mul.exe $precision @dims 5 | Add-Content matrix_timings.csv
        if ($LASTEXITCODE -ne 0) { throw "Matrix multiplication failed at $dims ($precision)" }
    }
}
```

The three timing columns are medians of five timed repetitions after one
warm-up. Plot them as stacked bars in a separate chart for each precision.
Compare the same dimensions and divide double times by float times.

## Q3. QFT on QuEST

```powershell
$source = (Get-Location).Path
git clone https://github.com/QuEST-Kit/QuEST.git
Set-Location QuEST
git checkout a61289550ab17a784739cde43094e0ec340dc648
Copy-Item (Join-Path $source 'qft_bench_naive.c') .
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_TRY_COMPILE_CONFIGURATION=Release `
  -DQUEST_ENABLE_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=120 -DCMAKE_CUDA_FLAGS=-lineinfo `
  -DUSER_SOURCE_NAMES=qft_bench_naive.c -DUSER_OUTPUT_EXE_NAME=qft_naive `
  "-DCMAKE_PROJECT_INCLUDE=$source/qft_build.cmake" "-DQFT_WINDOWS_COMPAT=$source/qft_windows_compat.h"
cmake --build build -j 4
.\build\qft_naive.exe 24 5
```

The Windows header supplies the benchmark's POSIX clock and `M_PI` without
changing its source. On Linux omit both Windows compatibility options, and
use `./build/qft_naive`. Change `120` to your GPU architecture.

```powershell
nsys profile --trace=cuda --sample=none --cpuctxsw=none --stats=true -o qft_24q .\build\qft_naive.exe 24 5
nsys profile --trace=cuda --sample=none --cpuctxsw=none --stats=true -o qft_16q .\build\qft_naive.exe 16 5
nsys profile --trace=cuda --sample=none --cpuctxsw=none --stats=true --cuda-memory-usage=true -o qft_28q .\build\qft_naive.exe 28 5
& (Join-Path $source 'measure_host_memory.ps1') .\build\qft_naive.exe
```

Windows Nsight Systems does not offer the `osrt` trace. On Linux, the
assignment's 24-qubit command is:

```sh
nsys profile --trace=cuda,osrt --stats=true -o qft_24q ./build/qft_naive 24 5
```

Repeat at 16 and 28 qubits. Add `--cuda-memory-usage=true` to the 28-qubit
capture. On Linux, `/usr/bin/time -v ./build/qft_naive 28 5` gives peak
resident host memory.

Read the 24-qubit top three rows from `cuda_gpu_kern_sum`. In the Nsight
Systems GUI, expand CUDA HW and the main thread's CUDA API row, zoom to a
timed repetition, and match `cudaLaunchKernel` to the GPU events. The
28-qubit Memory Usage track shows live device allocations. For exact
allocation and duration calculations, copy `read_qft_trace.py` next to
the three SQLite exports generated by `--stats=true`, then run it with
Python 3.
